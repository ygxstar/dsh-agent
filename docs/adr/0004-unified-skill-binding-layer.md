# 网关统一对接层：前端显式选技能，源图经工作区文件进入 DSH

网关要支持多种文生图/图生图技能，同时维持纯中转定位。我们决定：**前端在首条指令中显式指定技能**，网关用统一 command 信封（`skill + params + text`）对照**薄技能清单（Manifest）**做白名单与 JSON Schema 校验，再确定性序列化转发 DSH；提示词语义完全留在技能侧。同时决定：**源图不走 dsh-webapi `prompt.images` 字段**（当前版本编译产物中该字段的附件逻辑为空壳，不生效），而是上传至 DSH 会话工作区、prompt 附文件路径、由 agent 原生 `read_image` 读入。

## Considered Options

技能选择：

- **前端显式选择（选定）**：与 ADR-0002 的确定性命令白名单天然吻合；前端可按 Manifest 渲染差异化表单；任务内技能锁定可强制校验。
- **DSH 自动路由**：前端只发自由文本，由模型判断用哪个技能——"命令有效性"判断被推给 DSH，网关白名单形同虚设，且表单无法差异化。

差异层次：

- **薄 Manifest（选定）**：网关仅持有元数据（id、显示名、是否需源图、参数 schema），用于表单渲染与格式校验；每新增技能只加一条配置，网关零语义代码。
- **网关厚差异**：网关按技能拼装提示词模板——提示词知识散进网关，违背纯中转定位，且每加技能都要改网关代码。

源图路径：

- **工作区文件 + `read_image`（选定）**：当前 dsh-webapi 版本即可跑通，链路确定性。
- **依赖 `prompt.images` 字段**：需先修复/升级上游（可并行提 issue，修复后网关内部切换，不动接口）。
- **base64 内联 prompt 文本**：模型视觉通常不解析文本内 base64，不可靠。

## Consequences

- 新增技能 = 在网关 Manifest 增加一条配置 + DSH 侧安装技能；网关代码不变。
- 网关消息组装仅为"字段 → JSON 序列化"，仍属确定性规则，不违 ADR-0002（无 LLM、无提示词语义）。
- 源图链路依赖 dsh-webapi 的会话文件路由与 DSH 的 `read_image`；若上游修复 `images` 字段可无接口变更地切换。
