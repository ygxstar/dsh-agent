# 批量出图聚合在任务层：任务内出图单元，而非令牌列表

业务需要批量出图模式（1 图×4 技能、4 图×1 技能、2 图×3 技能等）。这些模式与既定的"一令牌一任务、首条单源图、任务内技能锁定"直接冲突。我们决定：**批量聚合在任务层**——一令牌仍绑定一个任务，任务内含 N 个**出图单元**（Cell = 源图 × 技能）；"技能锁定、单源图、首传仅一次"下沉为单元级规则，任务状态是各单元状态的聚合。

## Considered Options

- **任务内出图单元（选定）**：一令牌一任务不破，全部既有校验在单元级原样复用；前端一条 WS 看整张网格，断线恢复只重连一次。单元映射独立 DSH 会话，格间并行且技能上下文隔离。
- **令牌层展开（签发返回 token 列表）**：每格一个令牌/任务，规则零改动——但"一个用户凭据看全部"变成前端同时管理 N 条 WS 连接的聚合视图，复杂度外溢给前端，断线恢复需重连 N 次。
- **整批单会话串行**：多技能指令混在同一上下文，先后顺序互相影响出图，且无法并行。

## Consequences

- 单元由首条指令按 `imageRefs × skillIds` 笛卡尔积展开（可叠加签发侧 `preset` 约束），1×4、4×1、2×3 无特例。
- 修改逐单元（带 `cellId`，沿用该单元技能），确认整批一次；失败单元级隔离、可单格重试。
- 接口全线携带 `cellId`（单单元任务 = 1 格，无双 schema）；会话映射由 1:1 修订为任务↔会话 1:N。
- 规范见 [docs/gateway-interface.md](../gateway-interface.md)，术语见 GLOSSARY「出图单元」。
