# 任务只读分享用独立 share token，不复用登录令牌

任务（如 `task_bkGEG4PXxRee`）需要只读分享给好友查看。我们决定：**为每个任务签发独立的只读分享令牌（`sh_*`）**——链接形如 `/task/:id?sh=<token>`，携带 `sh` 参数即进入只读模式；登录令牌 `tk_*` 永不下发出分享链路。

## Considered Options

- **独立 share token（选定）**：同一路由两种模式，TaskPage 按 `sh` 参数裁剪为只读；令牌存内存 Map，与任务同生同灭（24h TTL），单任务至多一个有效、重新分享即轮换，关闭分享删除条目立即 403。WS `auth` 带 `role: "viewer"`，`command`/`confirm` 对 viewer 直接拒绝。
- **复用 `tk_*` 直接发给好友**：零建设成本，但 `tk_*` 是全权限一次性令牌，好友可下发指令、确认完成，且令牌用后即废的语义被破坏。
- **独立 `/share/:token` 路由 + 精简只读页**：需新增页面与跳转，且与任务页内容必然逐渐分叉，违背"分享视图与所有者完全一致"的目标。

## Consequences

- 权限分层清晰：**登录令牌**全权限一次性（GLOSSARY 既有语义不变），**分享令牌**只读、可轮换、随任务过期。
- 撤销 = 删除内存条目，已打开的 viewer 下一次请求即 403；代价是网关重启后分享链接全部失效——与任务本体 24h 内存 TTL 一致，可接受。
- 分享内容与所有者视图同源（复用 TaskPage 仅裁剪编辑控件），无双页同步成本。
- `/files/:ref` 图片端点本就近公开，只读视图直接复用，无需改造。
