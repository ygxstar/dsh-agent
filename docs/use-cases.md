# 用例（Use Cases）

网关的用户场景与角色说明（接口规范见 [gateway-interface.md](gateway-interface.md)，术语见根目录 GLOSSARY）。

## 角色

- **后台管理员（Admin）**：按商品规格型号接收客户下单的一方，人工或由商户订单系统自动调用签发 API；商品发货时向客户交付订单绑定的收货码。
- **下单客户（Customer）**：拿到收货码后登录前端系统，凭领取到的一个或多个令牌，按任务要求执行生图任务并确认收货。

## 场景 1：接单签发 → 发货给码 → 客户登录（端到端）

1. 管理员（或订单系统，内网直调）按订单调 `POST /admin/tokens`，传 `orderRef` 与每任务的 `preset`（可用技能集、最大格数、预填参数/文字）——**任务要求随签发注入**；
2. 签发返回 `{ redeemCode, expiresAt, tokens: [{token, taskId}] }`；
3. 商品发货时，管理员把**收货码**交付客户（收货码与订单绑定）；
4. 客户在前端 `POST /redeem {code}` 领取令牌列表（有效期内可重复领取，单码限频）；
5. 客户对每个令牌走 `POST /auth` / WS `auth {token}` 登录，查看任务要求表单。

## 场景 2：按任务要求执行生图（含 1×4 / 4×1 / 2×3）

客户上传参考图后，首条 `command` 以 `imageRefs × skillIds` 笛卡尔积展开出图单元：

| 模式 | 展开参数 | 结果 |
|---|---|---|
| **A：1×4** | 1 张源图 × 4 个技能 | 4 格，同图四种风格 |
| **B：4×1** | 4 张源图 × 1 个技能 | 4 格，同技能逐图出图 |
| **C：2×3** | 2 张源图 × 3 个技能 | 6 格 |
| 纯文生图 | `imageRefs: []` × N 技能 | N 格，每技能一张（`sourceRef` 为空） |

- 每格独立 DSH 会话，网关按并发上限调度，前端经带 `cellId` 的 `progress` / `result` 事件感知每格进度；
- 首条指令在签发侧 `preset` 约束内展开：技能白名单、格数上限、预填参数。

## 场景 3：修改、失败与确认

- **逐格修改**：不满意的格带 `cellId` 发修改指令（沿用该格技能），`editTarget` 只能指向同格产出；
- **失败隔离**：单格失败只标记该格（`DSH_FAILED` / `DSH_TIMEOUT`），其余格继续，失败格可单独重试；不阻塞整批确认；
- **整批确认**：一次 `confirm`（满意度评分）将全部格置为 DONE、令牌作废、任务终结；
- **断线恢复**：重连 `auth` 返回全部格快照（状态 + 产出图），图墙原地重建。

## 场景 4：码过期 / 吊销 / 异常

| 异常 | 行为 |
|---|---|
| 收货码错误/过期/被吊销 | `REDEEM_INVALID / REDEEM_EXPIRED / REDEEM_REVOKED`；码吊销联动作废未使用令牌 |
| 令牌被占用（另一连接已登录） | `TOKEN_INVALID` |
| 24h 未确认 | 任务 `EXPIRED`，令牌作废 |
| 码被高频尝试 | 归 `LIMIT`（单码领取限频） |
