# 团队编排协作规范
## 使用场景
主控需要拆分任务、委派给 dev / qa / sec / doc，支持随时打断、取消、并行后台任务时启用。

## 核心规则
1. **中断优先级**：用户指令 > 正在运行任务 > 排队任务。
2. **任务生命周期**：创建 → 排队 → 运行 → 完成 / 失败 / 取消。每个任务必须携带唯一 Task ID。
3. **并行约束**：同一个文件可以被多个子代理读，但尽量避免同时写；写同一个文件的任务串行排队，主控负责互斥调度。
4. **结果收敛**：子代理不直接互相对话；所有信息汇聚到主控，由主控合并、冲突裁决、再分发。
5. **取消语义**：收到取消指令，通知对应子代理立刻停止；开发子代理尽可能回滚临时改动。
6. **看板约定**：每次回复附带精简看板，不要刷屏。

## 取消模板

## 合并规则
当多个子代理返回冲突结论（QA 不通过 / 安全高危）：
- 高危安全、P0 bug：标记阻断，不进入下一环节；通知开发修复后重新触发 QA + SEC。
